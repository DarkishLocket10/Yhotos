# 022 Piwigo migration: missing storage prerequisite

Task 022 cannot currently read the Piwigo originals while satisfying the
repository's path-handling and scope rules.

## Evidence

- `AGENTS.md` requires every path derived from untrusted database text or
  filenames to go through the storage layer's safe-join. The exception for
  trusted command-line paths covers the upload root, not the `piwigo_images.path`
  values used to locate individual originals.
- `docs/architecture.md` section 5 describes an exposed storage `safe_join`, and
  `docs/threat-model.md` section 4.1 requires that storage constructor for paths.
- In this checkout, `crates/yhotos-storage/src/lib.rs` declares `mod paths`
  privately and does not re-export `safe_join`. In `src/paths.rs`, both
  `Component` and `safe_join` are `pub(crate)`.
- The public storage readers accept content hashes and derivative keys, or
  storage-owned temporary-upload UUIDs. They cannot open an existing Piwigo
  original by a validated relative source path. Its content hash is not known
  until the file is read.
- Task 022 permits changes to the migration binary, database additions, runbook,
  and the explicitly listed supporting areas. `yhotos-storage` is not included.

Constructing source paths inside the migration binary, copying the private
safe-join implementation there, or including its source file would bypass the
required storage boundary. Editing the storage crate would exceed this task's
scope. This is a missing prerequisite crate API, rather than a missing manifest
line or module wiring.

## Required decision

Provide a public storage API for opening read-only source files beneath a
canonical source root, or explicitly extend task 022's scope to add that API to
`yhotos-storage`. It must validate relative components, reject traversal,
absolute paths, symlinks and non-regular files, preserve root containment, and
work without creating or modifying anything in the source tree. The importer
can then stream those handles into `Store::put_original`.

No migration implementation, schema change, dependency, CI change, or source
database access was made. The maintainer's real-snapshot dry run and attached
output remain required after implementation.
