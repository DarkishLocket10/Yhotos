# 011 Public pages: home, album, photo, with the responsive image markup

## Goal

The public gallery is browsable: home lists top-level albums with covers, album pages show a justified grid of visible photos with correct `<picture>` markup, pagination, sorting, and nested child albums; photo pages show the image at the right size with EXIF, download menu, and Open Graph tags; legacy Piwigo URLs redirect. Pages are server-rendered, work without JavaScript, carry no layout shift, and hit the page-weight budgets. The lightbox island and theming layers come in later tasks; this task lays the HTML and CSS foundation they build on.

## Design

### Queries (one round trip each, visibility applied in SQL for pagination correctness)
This task introduces the SQL form of the access rules, as a `visible_photos(principal)` CTE fragment generated by a Rust function in `yhotos-db::access_sql` that binds the principal's user id and group ids. It must produce exactly the same decisions as `yhotos-core::access`; a test generates random album trees and principals, computes visibility both ways, and asserts equality (property test, 500 cases).
- Home: top-level visible albums with cover derivative hashes and photo counts (counting only visible photos).
- Album page: album by slug path (+ ancestors for breadcrumbs), visible child albums with covers, visible photos page with derivatives as a JSON array of `{variant, format, hdr, hash, w, h}`, total count. Page size 60, `?page=N`, `?sort=taken|posted|name|manual`.
- Photo page: photo by short id with its album chain, derivatives, metadata, previous/next short ids within the same album and sort (one window-function query).
- Legacy redirects: `/legacy/*` and the exact Piwigo patterns `index.php?/category/{id}`, `index.php?/category/{id}-{slug}`, `picture.php?/{id}/category/{cid}` are parsed and looked up in `legacy_redirects` (by id or slug as stored); hit → 301 to the new URL, miss → 404.

### Markup
- Justified grid computed server-side: rows are laid out by aspect ratio for a configured target row height (280 px) and a max row width (the container, assumed 1200 px for the server pass), producing per-image flex-basis percentages, so the grid is correct before any JS and never shifts. A `ResizeObserver` is not needed; the CSS uses the aspect ratio and `flex-grow` from the server numbers.
- Each image: `<picture>` with JXL, AVIF, JPEG sources, `srcset` of every width available, `sizes` derived from the grid cell's percentage, `width`/`height`, `loading="lazy"` except the first row, `decoding="async"`, `alt` from title, a `style="background-color: #rrggbb"` from the dominant color and a `data-thumbhash` attribute. The first row gets the thumbhash rendered server-side to a tiny data-URI PNG (implement the thumbhash decoder in Rust in `yhotos-core::thumbhash`, with the reference vectors).
- Photo page: `<picture>` sized to the viewport with `sizes="100vw"`, HDR variant via `<source media="(dynamic-range: high)">` when available, `<a href="/o/...">` download links per size, EXIF list, map link if gps, breadcrumbs, prev/next links with `rel`.
- Open Graph: `og:title`, `og:description`, `og:image` (the `large` JPEG derivative, absolute URL from `public_base_url`), `og:image:width/height`, `og:type`, `twitter:card=summary_large_image` on album and photo pages.
- `<link rel="prefetch">` is not used; prefetch-on-hover is a later island.
- RAW photos show a "RAW" badge; videos show a poster with a play badge (video playback is a later task).
- `404.html` is served for not found and for restricted content; the body is identical.

### CSS
`app.css` hand-written, no framework, under 30 KB uncompressed for this task. Design tokens as CSS variables on `:root` with a `prefers-color-scheme: dark` block; values are placeholders that the theme editor will override (task 016). System font stack. No external requests.

### Caching headers
Public pages: `Cache-Control: public, max-age=60, stale-while-revalidate=600`, `Cache-Tag: album:<id>` (and `photo:<id>`), `Vary: Cookie`. If the request has a session or share-link cookie, `private, no-store`.

### Tests
- Snapshot tests (`insta`) of the rendered HTML for a fixture album with 3 photos, in both anonymous and user-with-grant views.
- Property test: SQL visibility equals `yhotos-core::access`.
- Pagination: page past the end is 404; `per_page` is not user-controllable.
- Sort options produce the expected order; invalid sort falls back to default (no error).
- Restricted album by direct slug: anonymous gets the 404 page byte-identical to a missing slug.
- Legacy redirect table drives 301s; unknown legacy URL is 404; the target is always a relative path (test rejects a stored absolute URL).
- Query count test: album page = 3 queries (album chain, photos page, child albums) or fewer; photo page = 2 or fewer.
- Every `<img>` has width and height; HTML size for a 60-photo page under 30 KB gzipped (test compresses the snapshot).
- XSS: a photo titled `<script>alert(1)</script>` renders escaped in every place it appears (title, alt, og tags, JSON islands data).

### Bench
`pages.rs`: album page render with 60 photos from an in-memory row set (template + grid math) under 2 ms; with the DB warm under the budget in `docs/performance.md`.

## Security notes

- Threat model 4.4: askama escaping everywhere; JSON embedded for islands uses `serde_json::to_string` and is placed in a `<script type="application/json" nonce=...>` with `</` escaped as `<\/`.
- 4.3: restricted and missing are indistinguishable.
- Legacy redirects only to relative paths from the table.
- Allowed new dependencies: `insta` (dev), `flate2` (dev, for the size test), `png` (tiny encoder for placeholder data URIs; or hand-write an uncompressed PNG writer, 60 lines, preferred).
