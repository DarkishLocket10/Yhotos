# 005 Authentication primitives

## Goal

`yhotos-auth` provides the cryptographic and policy building blocks every later auth feature uses, with no HTTP and no database: password hashing and verification, opaque session and share tokens with hashed storage form, TOTP, WebAuthn (passkey) registration and authentication ceremonies, encryption at rest for MFA secrets, and the lockout policy state machine. Everything is constant-time where it must be, tested against known vectors, and fuzzed where it parses.

## Design

### Passwords
```rust
pub struct PasswordHash(String);              // PHC string, argon2id, m=65536 KiB, t=3, p=1, 16-byte salt
pub fn hash_password(pw: &SecretString) -> Result<PasswordHash, AuthError>;   // rejects < 8 or > 256 bytes
pub fn verify_password(pw: &SecretString, hash: &PasswordHash) -> Result<bool, AuthError>;  // never panics on malformed hash: returns Err
pub fn dummy_verify();                          // runs a verify against a fixed hash so unknown-user paths take the same time
pub fn needs_rehash(hash: &PasswordHash) -> bool; // params below current
```
Password policy (`check_password_policy`): minimum 12 characters for new passwords, maximum 256, not equal to username, not in a small embedded list of the 10k most common passwords (embed as a sorted `&[&str]`, binary search). Temporary passwords generated by `generate_temp_password()`: 20 chars from an unambiguous alphabet, from `OsRng`.

### Tokens
```rust
pub struct Token([u8; 32]);                    // 256 random bits from OsRng
pub struct TokenHash([u8; 32]);                // BLAKE3 keyed hash with a domain separator
pub enum TokenKind { Session, ShareLink, Csrf, PasswordReset }
impl Token {
  pub fn generate() -> Token;
  pub fn encode(&self, kind: TokenKind) -> String;        // "<prefix>_<base64url no pad>", prefix: ys, yl, yc, yr
  pub fn decode(s: &str) -> Result<(TokenKind, Token), AuthError>;  // strict: length, alphabet, prefix; constant-time where it matters
  pub fn hash(&self, kind: TokenKind) -> TokenHash;        // blake3::keyed_hash(derive_key("yhotos token v1 <kind>"), bytes)
}
impl TokenHash { pub fn ct_eq(&self, other: &TokenHash) -> bool; }  // subtle
```
`Token` implements `Zeroize` on drop and a `Debug` that prints `Token(<redacted>)`.

### Sessions policy
```rust
pub struct SessionPolicy { pub idle: Duration, pub absolute: Duration }   // defaults 14 d idle, 90 d absolute; admin 12 h idle, 7 d absolute
pub fn session_state(created_at, last_seen_at, now, policy) -> SessionState { Active, ExpiredIdle, ExpiredAbsolute }
```

### Lockout
```rust
pub struct LockoutPolicy { pub free_attempts: u32 (5), pub base_delay: Duration (30 s), pub max_delay: Duration (1 h) }
pub struct LockoutState { failures: u32, locked_until: Option<Timestamp> }
impl LockoutState { pub fn check(&self, now) -> Result<(), LockedUntil>; pub fn record_failure(&mut self, now, policy); pub fn record_success(&mut self); }
```
Exponential: after the free attempts are used up, the first lockout is `base`, then it doubles: delay = base * 2^(failures - free - 1) for failures > free, capped at max. So with the defaults, failures 1 to 5 are free, the 6th failure locks for 30 s, the 7th for 60 s, the 8th for 120 s. Pure, tested.

### TOTP
`totp::generate_secret() -> Secret (20 bytes)`, `totp::provisioning_uri(issuer, account, &secret)`, `totp::verify(&secret, code: &str, now, last_used_step: Option<u64>) -> Result<u64 /*step*/, AuthError>`: SHA1, 6 digits, 30 s, accepts step -1..=+1, rejects a step <= last_used_step (replay). Test vectors from RFC 6238 Appendix B (adapted to 6 digits/SHA1) must pass.

### WebAuthn
Wrap `webauthn-rs`: `Passkeys::new(rp_id, rp_origin)`, `start_registration(user_id, username, existing_credential_ids) -> (CreationChallengeResponse, RegistrationState)`, `finish_registration(state, response) -> Passkey (serialized)`, `start_authentication(passkeys) -> (RequestChallengeResponse, AuthenticationState)`, `finish_authentication(state, response) -> AuthenticationResult { credential_id, new_sign_count, user_verified }`. Require user verification for the admin flow (`UserVerificationPolicy::Required`, selected by a parameter). States are `serde` serializable so the HTTP layer can keep them in a short-lived server-side store (not in a cookie).

### Encryption at rest
`Keyring::from_master(key: &SecretString /* 32 bytes base64 */)`, `keyring.seal(aad: &[u8], plaintext: &[u8]) -> Vec<u8>` and `open` using XChaCha20-Poly1305 with a random 24-byte nonce prepended and a 1-byte version prefix. `aad` is the row id so a ciphertext cannot be moved between rows.

### Fuzz
`token_parse.rs`: `Token::decode` on arbitrary strings never panics; `PasswordHash` parsing never panics; `totp::verify` with arbitrary code strings never panics.

### Bench
`auth.rs`: `verify_password` (expect ~100 to 300 ms, that is intended), `Token::decode` + `hash` (under 1 µs), `totp::verify` (under 5 µs).

## Acceptance

- [ ] Known-answer tests: argon2id against a vector generated with the reference implementation (include the vector and how it was produced in a comment); RFC 6238 vectors; XChaCha20-Poly1305 vector from the crate's test suite or libsodium docs.
- [ ] `verify_password` on a malformed hash returns `Err`, not panic (test).
- [ ] `dummy_verify` timing is within 20 % of a real failed verify (test with 5 samples; mark `#[ignore]` if flaky in CI but keep it runnable).
- [ ] `Token::decode` rejects wrong prefix, wrong length, padding, non-url-safe chars; accepts its own `encode` output; property test for roundtrip.
- [ ] `TokenHash::ct_eq` uses `subtle`; `Token` and `Secret` zeroize on drop (test via `Zeroize` trait bound and a debug-format assertion that nothing leaks).
- [ ] Lockout state machine table test: 5 free attempts, then 30 s, 60 s, 120 s ... capped at 1 h; success resets.
- [ ] TOTP replay: the same code twice in one step fails the second time.
- [ ] WebAuthn: a full registration and authentication roundtrip using `webauthn-rs`'s software authenticator (`webauthn-authenticator-rs` soft token) in a test.
- [ ] Keyring: tampering with any byte fails `open`; wrong aad fails; versions prefix checked.
- [ ] Fuzz target builds and runs 60 s without a crash (record in PR).
- [ ] Benchmarks exist and numbers are in the PR.
- [ ] `scripts/check.sh` passes.

## Security notes

- Threat model 4.2 is the checklist for this task. The PR must map each bullet of 4.2 to the function and test that implements it, or say "HTTP layer, later task" where that is true.
- No logging anywhere in this crate.
- Allowed new dependencies: `argon2`, `password-hash`, `rand` (with `OsRng`), `subtle`, `zeroize`, `blake3`, `base64`, `totp-rs` or hand-written HMAC via `hmac`+`sha1` (hand-written preferred, it is 40 lines and avoids a dependency; include vectors), `webauthn-rs` (+ `webauthn-authenticator-rs` dev-dep), `chacha20poly1305`, `secrecy`, `serde`, `proptest`. Justify each in the PR.

## Performance

- Argon2 parameters are a security choice, not a performance one; do not lower them. Note the measured verify time in the PR so the HTTP layer can size its rate limits.

## Not in this task

- Login handlers, cookies, CSRF middleware integration, MFA enrollment pages, session storage in Postgres.
- Email codes (code path exists later, switched off).
