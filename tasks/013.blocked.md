# Task 013 blocked: task 010 authorization prerequisite is missing

Task 013 requires the lightbox and JSON API to honor verified share-link
capabilities for original downloads, likes, and flags. Its read-first list names
task 010, but its dependency list contains only task 011. Task 011 is present;
the task 010 HTTP/session integration is absent in this checkout.

## Evidence

- `crates/yhotos-http/src/middleware/session.rs`: `SessionIdentity` has only
  `Anonymous` and `User` variants. The loader resolves user sessions only. There
  is no verified share-link identity carrying a link id or capabilities.
- `crates/yhotos-core/src/access.rs`: `Principal::ShareLink` contains only its
  target. It cannot convey `link_id`, `allow_download`, `allow_like`, or
  `allow_flag`, which task 010's session design requires.
- `crates/yhotos-http/src/lib.rs`: the public router has no share landing or
  unlock routes, and there is no `crates/yhotos-http/src/share/` implementation.
- `crates/yhotos-http/src/files/mod.rs`: the original handler passes only
  `identity.principal()` to the shared file handler; authorization checks photo
  visibility, without a share-link download capability check. Task 013 explicitly
  requires original-download caps to be enforced by the server.
- The database share-link repository and attributed-like actor type exist, but
  neither supplies an authenticated link context to HTTP handlers. Database rows
  alone cannot safely establish the caller's identity or permissions.

## Why this blocks the brief

The required capability checks cannot be implemented against the current
verified-principal API. Accepting capabilities or link ids from island JSON,
request parameters, or client-side button visibility would not establish
authorization. Denying every share-link action would also fail the requirement
that authorized link holders can use their granted actions.

Providing the missing context requires task 010's authentication work: scoped
share sessions, token validation and revocation, capability-bearing identities,
user/link access union, and original-download enforcement. That is a separate
feature outside task 013's island and API scope, rather than supporting router
wiring or a missing manifest entry.

Per AGENTS.md's instruction to stop and record missing prerequisite crate APIs,
no partial gallery implementation or authorization workaround was added.

## Required resolution

Merge task 010 and make it an explicit prerequisite of task 013, then rerun this
task against the capability-bearing HTTP/session and file-serving interfaces.
Alternatively, the maintainer can revise the brief to explicitly defer all
share-link behavior. The original task brief and docs were left unchanged.
