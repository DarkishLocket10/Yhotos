Synthetic 1.2-second, 128x96 10fps moving test pattern with a generated 880Hz tone.
All three files are below 300 KB. No camera footage or personal metadata.

Generated locally with ffmpeg 6.1.1:

```
ffmpeg -f lavfi -i testsrc2=size=128x96:rate=10 -f lavfi -i sine=frequency=880:sample_rate=44100 -t 1.2 -c:v libx264 -profile:v high -pix_fmt yuv420p -c:a aac -b:a 32k -movflags +faststart h264.mp4
ffmpeg -display_rotation:v:0 90 -i h264.mp4 -c copy rotated.mov
ffmpeg -i h264.mp4 -c:v libx265 -x265-params pools=1:frame-threads=1:log-level=error -c:a copy -tag:v hvc1 hevc.mov
```

`rotated.mov` has a 90-degree display matrix, representing iPhone-style portrait
orientation without rotating stored pixels. Malformed files are generated by tests;
the duration rejection uses this same real sample with a one-second configured cap.

The 4K publication regressions use a synthetic five-frame, one-second HEVC MOV
at 3840x2160, and a copy with a 90-degree display matrix. Both are under 300 KB.
Generated locally with the digest-pinned static ffmpeg from `deploy/dev/video-tools.sh`:

```
target/video-tools/ffmpeg -v error -f lavfi -i color=c=navy:s=3840x2160:r=5:d=1 -c:v libx265 -preset ultrafast -x265-params pools=1:frame-threads=1:log-level=error -pix_fmt yuv420p -tag:v hvc1 -an -map_metadata -1 4k-landscape.mov
target/video-tools/ffmpeg -v error -display_rotation:v:0 90 -i 4k-landscape.mov -c copy 4k-portrait.mov
```

The anamorphic regressions retain the 128x96 coded frame with SAR 2:1
(display size 256x96, ratio 8:3), plus a 90-degree rotated copy. Both are
under 300 KB and use the same synthetic source:

```
target/video-tools/ffmpeg -v error -i h264.mp4 -vf setsar=2/1 -c:v libx264 -profile:v high -pix_fmt yuv420p -c:a copy -movflags +faststart anamorphic.mp4
target/video-tools/ffmpeg -v error -display_rotation:v:0 90 -i anamorphic.mp4 -c copy anamorphic-rotated.mov
```

`color-*.mp4` are one-second, 144x96 synthetic three-patch SDR samples, each
under 300 KB. Regenerate with `python3 fixtures/video/generate-colors.py` after
`deploy/dev/video-tools.sh`. Cases cover tagged BT.601 (525 and 625 line
primaries), BT.709, Display P3 with sRGB transfer, BT.709 with sRGB transfer,
BT.2020 SDR, full-range BT.709 and untagged SD camera YCbCr.

The generator computes `color-reference.json` independently of ffmpeg using
YCbCr coefficients, inverse transfer functions and D65 RGB/XYZ matrices.
Tests decode both renditions as BT.709 RGB and measure a 16x16 area at each
patch's centre. Each channel must be within 5/255 of the reference, allowing
8-bit YCbCr quantization and the prescribed lossy encoders. Merely changing
tags fails the BT.601 (525-line), P3, sRGB and BT.2020 cases.

Missing tags use conventional camera defaults before rotation/SAR adjustment:
SD YCbCr uses BT.601 (525-line at up to 486 pixels high, otherwise 625-line at
up to 576; coded width at most 1024), HD uses BT.709, and range defaults to
limited. Present matrix/primaries tags take precedence; partially tagged P3
defaults to sRGB transfer and HDR to BT.2020 primaries/matrix. Entirely
untagged wide-gamut footage cannot be identified from pixels alone.
