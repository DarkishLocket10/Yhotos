# Synthetic HDR fixtures

All images use original synthetic chart data and the committed sRGB/P3 profiles.
No owner-library original or internet image is used. Every fixture is under 300 KB.

- `iso.jpg`: ISO 21496-1 JPEG generated by libultrahdr's compressed-base/map API.
- `iso-p3.jpg`: the same gain-map layout with a Display P3 base and embedded ICC.
- `adobe.jpg`: the same base/map with Adobe hdrgm metadata and MPF, without ISO APP2.
- `apple.heic`: synthetic HEVC base and half-resolution auxiliary, standard Apple
  auxiliary URI/association, namespaced HDRGainMapVersion 65536, and only a minimal
  EXIF MakerNote containing float32 keys 33=1 and 48=0 (three stops headroom).
- `apple-element.heic`: the same base, auxiliary and MakerNote, with Apple's
  gain-map version as an RDF/XML property element instead of an attribute.
  `apple-attribute.xmp` and `apple-element.xmp` are the complete embedded XMP
  packets, including Apple's auxiliary-image type and gain-map namespaces.
  Both use synthetic chart pixels; neither claims owner-library provenance.
- `gain-map.jxl`: naked libjxl base/map streams in a `jhgm` bundle with ISO metadata.
- `gain-map-brob.jxl`: the same base and bundle, with `jhgm` wrapped in a Brotli
  `brob` box. This exercises the intentional SDR fallback and its recorded reason
  `compressed JPEG XL gain map not supported`.
- `../images/gain-map.avif`: libavif-generated tmap/AV1 source; its generator is in
  `scripts/gen-fixtures.sh` and it contains no XMP signature substitutes.

Run `scripts/gen-fixtures.sh --hdr` offline with vips, libheif's HEVC encoder,
libjxl, libbrotlienc, libuhdr and a C compiler. `generate.py` and `mux.c` contain the full recipe.
Apple semantics follow [Apple's published algorithm](https://developer.apple.com/documentation/appkit/applying-apple-hdr-effect-to-your-photos).
The JXL bundle follows [libjxl's reference layout](https://github.com/libjxl/libjxl/blob/main/lib/extras/gain_map.cc).

`generate.py --orientations` generates the committed `orientation/` matrix using
`orientations.py` and `orientation-jxl.c`, with the same offline libraries. Each
96x64 base and 48x32 map has four distinct grayscale quadrants (224, 48, 96, 160).
The base uses orientations 1 through 8; every auxiliary deliberately uses the
conflicting orientation `9 - base_orientation`. JPEG ISO/Adobe and JXL use their
native orientation metadata. HEIC Apple and AVIF tmap include both EXIF-only and
irot/imir cases for all eight equivalent EXIF transforms. The HEIF loader treats
EXIF orientation as informational and uses irot/imir for display, as documented in
[libvips heifload](https://github.com/libvips/libvips/blob/v8.15.1/libvips/foreign/heifload.c#L602-L610).
The AVIF writer packages actual libheif-encoded AV1 items and ISO tmap metadata;
it needs no newer libavif encoder at test time. No fixture needs an encoder or
network at test time. All 56 fixtures are individually below 300 KB.
